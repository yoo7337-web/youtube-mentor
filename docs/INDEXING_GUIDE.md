# 인덱싱·큐레이션 가이드 (사고방식의 표준)

> 새 영상을 인덱싱하거나 새 인물을 추가할 때 **항상 이 문서대로** 한다.
> 목적: 누가/언제 하든 지식팩의 품질·형식·관점이 일관되게 유지되는 것.
> v1.0 — 2026-07-05, 1차(3명)+2차(7명) 인덱싱 실전 경험을 반영해 작성.

---

## 0. 대원칙 (모든 단계에 우선)

1. **근거주의** — 지식팩의 모든 내용은 자막에 실제로 있는 발언에서만 나온다.
   요약·의역은 허용하되, 자막에 없는 주장·수치·종목을 만들어내는 것은 절대 금지.
2. **지식 격리** — 전문가 A를 큐레이션할 때 다른 전문가의 지식팩·자막을 참조하지 않는다.
   한 영상에 여러 사람이 나오면(패널 방송) **그 전문가 본인의 발언만** 채택한다.
3. **시점 명시** — 모든 인사이트·인용에 영상 날짜(YYYY-MM-DD)를 붙인다.
   발언은 "그 시점의 견해"이며, 이후 뷰 타임라인·적중률 스코어카드의 원료가 된다.
4. **가치는 '관점'에 있다** — 단순 사실 전달(뉴스 요약)보다, 그 사람 특유의
   **판단·논리·원칙**이 드러나는 발언을 우선 채택한다.
5. **누적과 신선도** — 자막·인사이트는 절대 삭제하지 않고 계속 누적한다(견해 변화의
   기록 = 타임라인·스코어카드 데이터). 신규 큐레이션은 **최근 3개월 내 영상을 우선**하되,
   원칙·사고방식 인사이트는 시효 없이 채택한다. 상세 규칙은 §3.6 시점 정책.

## 1. 파이프라인 (3단계, 순서 고정)

```
① 수집   python src/collect_transcripts.py <slug…|--all> [--limit 50] [--delay 8] [--max-new 20]
          → data/transcripts/<slug>/<video_id>.json  (증분: 기존 영상 스킵)
② 큐레이션 Claude가 자막을 읽고 인사이트·인용 추출
          → data/knowledge-packs/_curated/<slug>.json  (사람이 아닌 Claude가 작성)
③ 조립    python src/build_knowledge_pack.py <slug…>
          → data/knowledge-packs/<slug>.json + manifest.json  (사이트가 즉시 반영)
```

- ②가 품질의 핵심. ①③은 기계적이며 스크립트가 처리한다.
- 큐레이션 없이 조립하면 insights가 빈 지식팩이 된다(경고 출력됨) — 반드시 ② 수행.

## 2. 수집 규칙 (collect)

- **소스 우선순위**: 본인 채널 > 본인 재생목록(월간 오건영 등) > 제3자 큐레이션 재생목록 > **수동 소스(X·뉴스레터·블로그, §7)**. (Threads는 제외 — §7 참고)
  제3자 재생목록은 편집·발췌본일 수 있으므로 persona YAML의 `note`에 출처 성격을 기록.
- **자막 언어**: ko 우선, 없으면 en (스크립트 기본값). 자동자막 허용.
- **자막 엔진**: yt-dlp(주, 플레이어 API 경유) → youtube-transcript-api(폴백). 스크립트가 자동 처리.
- **영상 목록 확보(15개 이상 백필)**: 유튜브 RSS는 채널당 **최신 15개까지만** 준다.
  `--limit 50`처럼 15를 넘기면 `yt-dlp --flat-playlist`로 옛 영상까지 목록을 얻어 백필한다(목록 조회는
  자막 API와 **다른 경로**라 IP 차단과 독립적으로 동작). 날짜는 flat 목록엔 없고, 자막 fetch 시
  같은 yt-dlp 추출에서 업로드일을 함께 캡처한다(추가 요청 없음). 최근 15개는 RSS의 정확한 날짜·한글 제목 우선.
- **IP 차단(429/IpBlocked) 대응**: 유튜브가 연속 자막 요청을 IP 단위로 차단한다. **두 엔진 모두 같은 IP를 쓰므로 도구를 바꿔도 소용없다**(WebFetch·전환사이트도 403/JS로 불가 — 검증됨).
  - 기본 `--delay 1.5`로 시작, 차단 감지 시 `--delay 8`로 재시도.
  - 8초에도 전량 차단되면 **중단하고 몇 시간 뒤(야간) 재시도**. 계속 두드리면 악화된다.
  - 자막 존재 여부는 `YouTubeTranscriptApi().list(video_id)` 단발 호출로 확인 가능.
  - **백필(50개)은 요청량이 많다** → `--max-new 20`으로 회당 신규 상한을 두고 **야간에 며칠 분산 수집**한다.
    이미 받은 영상은 자동 스킵되므로 같은 명령을 반복 실행하면 남은 것만 이어받는다.
    예) `python src/collect_transcripts.py --all --limit 50 --delay 8 --max-new 20` (야간 반복)
- **수집 안 되는 영상은 억지로 채우지 않는다** — 라이브 예고·공지·음악 영상 등은
  자막이 없거나 무의미. "자막없음"으로 스킵되는 것이 정상 동작.

## 3. 큐레이션 규칙 (핵심)

### 3.1 인사이트 스키마 (필드 전부 필수)

```jsonc
{
  "topic": "반도체/메모리",     // §3.2 표준 태그 사용
  "tickers": ["005930", "MU"],  // 한국=6자리 코드, 미국=티커. 언급 없으면 []
  "direction": "긍정",          // 긍정 | 부정 | 중립 — 그 주제에 대한 '그 사람'의 방향
  "kind": "시황",               // (선택) 시황 | 원칙 — 기본 시황. '원칙'=시효 없는 사고방식·프레임워크·투자철학
  "thesis": "2~4문장. 논거를 수치·근거와 함께. 자막에 있는 내용만.",
  "date": "2026-06-24",         // 영상 published 날짜
  "video": "https://www.youtube.com/watch?v=…"
}
```

- **kind 판정**: 특정 시점 시장·자산 전망 = `시황`(기본, 생략 가능). 시대와 무관하게 유효한
  판단 기준·프레임워크·투자 철학(해자, 2차적 사고, 사이클론, 물타기 금지 원칙 등) = `원칙`.
  서한·메모 등 문서 소스는 대부분 원칙. 소급 라벨링 불요(2026-07-06 이후 큐레이션부터).

- **분량**: 전문가당 인사이트 6~9개, 인용(quotes) 4~6개.
  영상이 1~2개뿐이면(임형록 사례) 그 안의 서로 다른 주제로 4~7개.
- **thesis 작성법**: "무엇을 주장했나"가 아니라 "**왜 그렇게 판단했나**"가 담기게.
  좋은 예: "5년 장기계약(테이크올페이)으로 최소 영업마진 52%가 확정됐기 때문에 메모리는 더 이상 사이클 산업이 아니다."
  나쁜 예: "메모리 산업을 긍정적으로 봤다." (논거 없음)
- **quotes**: 자막 원문 그대로(버바팀). 한국어 전문가는 한국어, 영어 전문가는 영어 원문 유지
  (thesis는 항상 한국어). 그 사람 특유의 표현·비유가 담긴 문장을 고른다.

### 3.2 topic 표준 태그 (대립 보드·타임라인의 축 — 일관성 필수)

`대분류` 또는 `대분류/소분류` 형태. 기존 지식팩과 **같은 주제는 같은 태그**를 쓴다.
새 태그를 만들기 전에 기존 지식팩들의 topic을 grep해서 재사용 가능한지 확인할 것.

현재 사용 중인 표준 태그(예시): `반도체/메모리` `빅테크/AI 케펙스` `거시/금리` `거시/연준`
`환율` `자산배분` `투자원칙/리스크관리` `시장 사이클` `AI/버블` `미국주식` `한국증시/수급`
`부동산` `크레딧/채권` `비트코인/크립토` `에너지`

### 3.3 direction 판정

- **긍정/부정**: 해당 주제·자산의 전망에 대한 그 사람의 방향성이 분명할 때.
- **중립**: 방향 없이 구조 설명, 조건부 판단("~라면 좋고 ~라면 나쁘다"), 원칙론.
- 애매하면 중립. direction은 적중률 스코어카드(v1.3)의 채점 대상이므로 과감히 붙이지 않는다.

### 3.4 채택·배제 기준 (실전에서 배운 것)

- **배제**: 광고·인사말·구독 요청, 라이브 예고/공지, 유료상품 안내, 잡담.
- **패널 방송**(삼프로TV·별주부전 등): 그 전문가 **본인 발언이 확실한 부분만**. 애매하면 버린다.
- **중복 영상**(같은 내용 재업로드): 하나만 사용.
- **오래된 발언**: 배제하지 않되 date가 정확해야 한다. 채널이 업로드를 멈춘 경우
  (86번가=2023, 린치=1990년대) 지식팩 `_note`와 페르소나 답변에서 시대를 명시하게 한다.
- **본인 소통정책**(종목 비공개 원칙 등)도 인사이트로 가치 있다 — 답변 태도를 결정하기 때문.

### 3.5 실행 방식 (컨텍스트 관리)

- 자막 총량이 크므로(전문가당 5만~40만자) 큐레이션은 **전문가별 병렬 서브에이전트**에 위임한다.
  메인 세션이 직접 읽는 것은 소량(영상 1~3개)일 때만.
- 서브에이전트 프롬프트 표준(요지): 대상 폴더 → 전 파일 Read → 위 §3.1~3.4 규칙 →
  `_curated/<slug>.json` Write → insights 개수·topic 목록만 보고.
  기존 예시는 `_curated/kimdante.json`을 참조 형식으로 지정한다.
- 자막은 자동생성이라 오탈자·구어체가 많다 — 문맥으로 이해하고, 인용은 원문 그대로 둔다.

### 3.6 시점 정책 (누적 + 최근 3개월 우선) — 사용자 확정 2026-07-05

**원칙: 저장은 전부 누적, 신규 큐레이션은 최근 우선, 답변 가중치는 사이트가 자동 처리.**

1. **신규 큐레이션 대상 선정**: 최근 **3개월 내** 영상의 발언을 우선 큐레이션한다.
   3개월 이전 영상은 다음 두 경우에만 채택 — ① 원칙·사고방식·프레임워크(투자 철학,
   판단 기준, 비유)가 담긴 발언 ② 그 전문가의 대표 논리로 볼 수 있는 발언.
2. **시황성 인사이트의 수명**: 특정 시점 시장 전망(시황)은 3개월이 지나도 **절대 삭제하지
   않는다** — 뷰 타임라인(v1.1)·적중률 스코어카드(v1.3)의 원료다. 오래됐다고 지우는 것은
   이 프로젝트의 데이터 자산을 버리는 행위.
3. **휴면 채널 예외**: 최근 3개월 내 업로드가 없는 채널(예: 버핏·린치·86번가)은 전체를
   '사고방식·원칙 참고'로 큐레이션하고, **시대(연도)를 반드시 명시**한다(§3.4와 연결).
   "최근 견해 없음"은 결함이 아니라 그 전문가의 특성이다.
4. **답변 시 가중치는 자동**: 사이트 `buildPrompt`(index.html)가 인사이트 date 기준
   90일로 "최근 3개월 견해(우선 반영)" / "과거 발언·사고방식(원칙 참고)"를 자동 분리해
   Gemini에 투입한다. 따라서 큐레이션 때 별도 신선도 라벨을 달 필요 없다 —
   **date 정확성만 지키면 정책이 저절로 작동한다.**

## 4. 증분 인덱싱 (기존 인물에 새 영상 추가 시)

1. ① 수집 실행 — 기존 영상은 자동 스킵, 새 영상만 받는다.
2. **새 영상 자막만** 읽고 새 인사이트·인용을 뽑는다. 새 영상 중 **3개월 내 영상을 우선**
   큐레이션한다(§3.6 — 백필로 받은 옛 영상은 원칙·사고방식 발언만 선별).
3. `_curated/<slug>.json`에 **append** 한다(기존 항목 삭제·수정 금지).
   - 같은 주제의 견해가 바뀌었어도 옛 인사이트를 지우지 않는다 —
     **견해 변화의 기록 자체가 뷰 타임라인(v1.1)의 데이터**다.
   - 단, 명백한 오류(오탈자, 잘못된 티커)는 수정 가능.
4. ③ 조립 실행 → manifest 자동 갱신 → 사이트 즉시 반영.

## 5. 새 인물 추가 체크리스트

1. **채널 확인**: WebSearch로 공식 채널/재생목록의 UC채널ID 또는 PL재생목록ID 확보.
   @handle만 알면 그대로 적어도 된다(수집기가 해석). 본인 채널이 없으면 재생목록 큐레이션.
2. **페르소나 YAML 작성**: `personas/_example.yaml` 복사 → slug(영문)·name·domain·channels·intro.
   (전문가 분류는 persona가 아니라 사이트 `data/categories.json`에서 관리 — 분류 탭에서 드래그로 배정)
   - `tone`: 그 사람의 **화법과 판단 프레임**을 2~3문장으로(예: "데이터·백테스트 기반의 냉정한 분석…").
   - `guardrails`: 공통 3종(매매지시 금지 / AI 재현 전제 / 근거 없는 주장 금지) + 인물 특성별 추가
     (예: 시황 발언 많은 인물 → "시점 명시", 영어 인물 → "번역 왜곡 금지", 옛 인물 → "시대 명시").
3. **로스터 갱신**: `docs/ARCHITECTURE.md` §5 표에 행 추가.
4. 파이프라인 ①②③ 실행 → 사이트에서 카드 확인.
5. 메모리(`project_youtube_mentor.md`)의 전문가 수 갱신.

## 6. 품질 자가검증 (조립 후)

**필수: `python src/verify_pack.py <slug…|--all>` 실행** — 인용 원문 존재(정규화 대조)·insight date/url 정합·
미큐레이션 자료 수를 자동 검사한다. ✗ 인용은 자막 원문으로 교체하거나 삭제(다듬은 인용은 버바팀 원칙 위반).
검증기는 보고만 하며 자동 수정하지 않는다. (2026-07-06 도입 — 첫 감사에서 기존 인용 28%가 원문 불일치로 적발됨)

- [ ] 인사이트마다 date·video가 실제 그 발언이 나온 영상과 일치하는가

- [ ] (터미널 상담 1회 시연) 지식팩만으로 근거 있는 답변이 나오는가

## 7. 수동 소스 인덱싱 (X · 뉴스레터 · 블로그 등) — 2026-07-05 신설

유튜브 외 텍스트 소스를 붙이는 통로. 원문을 넣으면 유튜브 자막과 **같은 스키마+`source` 태그**로
저장돼 이후 큐레이션·빌드·시점정책(§3.6)이 동일하게 적용된다.

> **※ Threads는 인덱싱 후보에서 제외**(2026-07-05, 사용자 결정). 비로그인 상태에서 **로그인 벽 전
> 최근 글 일부(≈7~10개)만** 접근되고 그 아래 과거 글은 로그인이 필요해 전체 수집이 불가능하기 때문.
> (사이트·스크립트 자동 수집은 원본 HTML에 글이 없어 애초에 불가.) 필요하면 그 글을 직접 복사해
> 아래 인박스에 붙여넣는 것은 언제든 가능.

### 7.0 1차 공식 문서 (자동 수집 — 최우선 소스, 2026-07-06 신설)

거장의 정수는 유튜브가 아니라 **공식 문서**에 있다. `python src/fetch_documents.py <marks|buffett|--all> [--limit N]`
- **marks**: Oaktree 메모(oaktreecapital.com/insights/memos) — 목록→본문 HTML 파싱, 게시일은 `<time>` 태그(본문 인용 날짜 오탐 주의)
- **buffett**: Berkshire 주주서한(PDF→pypdf 추출, 응답이 brotli 압축이라 brotli 패키지 필요)
- 저장: `data/transcripts/<slug>/doc_*.json` + `source:"memo"|"letter"` (증분 스킵). 큐레이션은 §3 그대로,
  **문서는 대부분 `kind:"원칙"`** · 인용은 영어 원문 버바팀(verify_pack이 대조 검증).
- 확장 시(달리오 에세이 등) 같은 패턴으로 fetcher 추가.

### 7.x 수동 붙여넣기 (X · 뉴스레터 · 블로그)

1. **인박스에 붙여넣기**: `data/manual/<slug>.md` (git 제외 — 원문은 저작권/개인). 포맷:
   ```
   ## 2026-07-01 | https://example.com/글주소
   본문 여러 줄...

   ## 2026-06-20 | https://...
   또 다른 글...
   ```
   헤더 `## <YYYY-MM-DD> | <url>`(url 선택). **날짜는 시점정책(§3.6)에 필수 — 반드시 기입.**
2. **인제스트**: `python src/add_source.py <slug…|--all> [--source x|web]`
   → `data/transcripts/<slug>/src_*.json` 레코드 생성(증분: 같은 글 스킵). source는 url로 자동판별.
3. **큐레이션**: §3·§3.6 그대로. **짧은 글은 게시글 단위로** 인사이트를 뽑고,
   인용(quotes)은 원문 그대로, date는 게시일. 유튜브 인사이트와 한 지식팩에 누적된다.
4. **빌드**: `python src/build_knowledge_pack.py <slug…>` → videos[]에 `source` 포함, 사이트가 소스 아이콘 표시.
